Database connections

Read-only credentials to your databases. Users never see these — they only pick from the tables you register.

CLIENT_ENCRYPTION_KEY is not configured on this server. Database connections cannot be saved until it is set in the environment and the container is restarted.

Give your users live database tables in three steps

  1. 1
    Add a connection
    Point PowerDataChat at a database with a read-only account. Credentials are encrypted and stay on this server.
  2. 2
    Register tables
    Pick tables, review the AI-drafted descriptions, and confirm. A local snapshot is taken — user questions never query your database directly.
  3. 3
    Users select them in chats
    Registered tables appear in the “Select from DB” list when users create a chat, refreshed nightly.

Users

Everyone who has signed in. Each user has ONE role that controls which registered database tables they can pick and refresh. Existing chats always keep their saved data.

Roles

A role grants access to registered database tables — explicit tables, or a whole schema/connection (which also covers tables registered later). Connector tables are always included automatically for joins. New users start in the built-in Base role.

Refresh schedule

Snapshots refresh automatically every night. A failed refresh keeps the previous snapshot — chats never break.

Audit log

Every administrative action, newest first. Credentials are never written here.
